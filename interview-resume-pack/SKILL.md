# 面试备战包生成（漏斗稿 + 深钻点 + 防守材料）

一句话：从已建档项目档案生成"漏斗式表达"全套面试材料。Hermes 编排+校验，agy 出稿，证据门防编造。
与面试三件套的关系：interview-bank-pipeline 管建档（生产端）→ 本 skill 管表达材料（生产端，拷打的**软前置**）→ agent-project-grill 管拷打（消费端：备战包缺失时提示生成但不阻塞；深钻点 L3 与不会题清单为优先出题源；复盘暴露的薄弱点以「备战包修订建议」回流复盘文件，积累 ≥3 条触发重生成）。

## 产出物六件套

输出到 `$INTERVIEW_WORKSPACE/obsidian_vault/40_项目档案/<slug>/备战包/`（INTERVIEW_WORKSPACE 未设置回退 `~/桌面/面试文档裁切`）：

1. `漏斗稿.md` — 30s / 3min / 10min 三版
2. `深钻点-<名称>.md` × 2-3 — 每点五层拆解，附证据锚点
3. `DHR卡.md` — 核心场景 Detection→Handling→Recovery
4. `不会题.md` — 极限题防守模板库
5. `组合failure.md` — 跨模块 worst-case 推演
6. `简历bullet.md` — 3-5 条主 bullet + 每条数字出处
7. `README.md` 总览页 — Hermes 生成（产物索引 + 拍板记录 + 待补清单）

## 0. 前置检查

- 定位 slug（owner__repo），检查 project-mock-interview `references/项目/<slug>/match.json`；不存在 → 先按 interview-bank-pipeline 建档再回来
- 读 vault 的 `学习卡.md` / `面试复盘.md` 待复习清单 + agent-project-grill 拷打记录的薄弱维度 → 作为深钻点选择输入

## 1. 深钻点选定（唯一用户拍板点）

判定标准 = 证据链三要素至少占二：
- A 真实数字（怎么测出来的）
- B 踩坑故事（怎么发现→定位→修→现在怎么防）
- C 被否决的替代方案（为什么不用 X）

- 从 `项目画像.md` + `项目内作答.md` 盘点每个候选模块的三要素存量，存量最厚的 2-3 个为默认
- 有用户在场 → clarify 拍板（推荐置首）；用户不在 → 按默认走并在 README 标注"可换"
- 同时产出**不深钻清单**：漏斗稿 30s 版绝不出现的模块名（排雷——没准备的东西一个字不出现，信息差是最大资产）

## 2. 派 agy 生成

任务包组装（Hermes 做，≤8K tokens）：
- 顶部放"生成原则"（见下）+ 上轮产物路径（续会话时）
- 输入切片：画像相关段 + 作答档相关 Lxx 段 + 证据锚点清单，禁整载档案
- 执行：按 agy skill 调用规范，自由版提示词触发其内评审，`-d`，报告只回改动清单；同链路续轮 `-c <conversation_id>` 承接
- 兜底：agy 不可用（认证过期/网络故障，恢复法见 memory）时 Hermes 直接按模板硬结构出稿并标注「降级出稿」，流程不阻塞；证据门标准不降
- 产物必须符合下方"模板硬结构"

## 3. 证据门（Hermes 校验，不过关打回 agy 重修对应段）

1. **锚点校验**：`python3 <本skill目录>/scripts/evidence_gate.py <产物> <仓库根>` — 路径:行号 锚点逐一 exists，悬空即 FAIL
2. **数字红线**：漏斗稿/简历bullet 中每个数字必须有档案/作答档/代码出处；找不到 → 标 `[待补]` 或删除，禁止保留无出处数字
3. **结构完整**：六件套齐全；每深钻点五层齐全；每不会题含四步
4. **名词密度红线**：不会题答案里方案描述用功能性描述（专有名词降级），钩子名词只允许出现在深钻点覆盖范围内
5. **排雷校验**：30s 版中不深钻清单的模块名零出现

## 4. 交付与回注

- README.md 总览页：产物索引 + 深钻点拍板记录 + [待补]数字清单
- 回注 agent-project-grill：深钻点 L3 层问题作为下一场拷打出题源（出题策略：备战包优先）
- 简历bullet 红线：与用户既有简历终稿冲突时以终稿为准（事实红线零回退），只增不改

## 生成原则（写进每次任务包顶部）

1. 漏斗 = 画地图，把面试官引进预设战场；30s 版是问题空间划定，不是项目总结
2. 深钻点 = 证据链三要素至少占二的 2-3 个点，其余模块只保"职责/接口/为什么存在/基本实现/failure mode"
3. 不会题 = 主动收刀：名词降级 + 具体数字划界；绝不"没考虑过"，绝不抛接不住的名词
4. 单模块 L3 之外必配组合 failure（模块A故障×模块B失效的传播链与断路设计）
5. 一切数字有出处，编造 = 打回（历史教训：agy 按八股"应该的样子"编造项目细节）

## 模板硬结构（agy 必须遵守）

- **漏斗稿 30s**：一个痛点 → 两分法拆解（如"选得准 / 加载得省"）→ 闭环拍点（评估体系）。禁模块名词罗列
- **漏斗稿 3min**：架构文字版 + 数据流 + 两分法各一段方案 + 为什么是这个拆法
- **漏斗稿 10min**：三个核心设计 × 每个（背景 / 方案 / 三要素证据链 / known limitation）
- **深钻点五层**：L1 为什么存在（含否决方案）/ L2 机制 + 参数怎么定 / L3 证据 + 反事实（怎么知道 work、什么时候挂、测试集怎么构造、规模×N 怎么办）
- **DHR**：场景 → Detection（信号/监控/日志）→ Handling（降级/兜底）→ Recovery（自愈/人工/数据修复）
- **不会题四步**：数字划界（benchmark 在 X 规模）→ 拆关注点（延迟/召回/成本）→ 功能性方案（名词降级）→ 验证计划（先测什么指标确认瓶颈）
- **组合failure**：A×B 组合 → 传播链 → 最坏状态 → 检测点 → 断路设计
- **简历bullet**：动词开头 + 机制一句话 + 数字结果；每条附出处（档案段落或 代码:行号）
