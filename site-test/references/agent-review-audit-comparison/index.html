    agent-review-audit 对比与融合计划（2026-08-11 评审）

    姊妹技能位置与结构

    • 路径：~/.gemini/antigravity-cli/builtin/skills/agent-review-audit/（用户 Antigravity/Gemini CLI 的内置 skill，与本技能并行）
    • 结构：SKILL.md（4.4KB 轻量路由表，6 大类）+ references/03_Cards/Q001~Q243.md（243 张题卡，~1MB）+ scripts/route_project.py（3.8KB，关键词路由）
    • 题源同族：243 卡与本题库 240 题同源（如 Q006≈L9），可做 Q↔L 映射

    题卡 schema（它比我们强的部分）

    frontmatter 字段：qid / title / primary_category / sub_category / depth_level / status(待复习) / tags / concepts / prerequisites / downstream 正文：[!QUESTION] 问题描述 + [!NOTE] 元数据与知识上下文 + [!SUCCESS] 答题思路与知识点分析

    • 每卡内嵌答题思路与知识点分析 —— 题目和答案一体，语料自带蒸馏（本技能 items.json 缺这一层）
    • prerequisites/downstream —— 学习路径有向边（真图谱）
    • status: 待复习 —— 间隔复习种子

    route_project.py 路由机制与局限

    • 机制：6 类关键词频次打分（×2/命中）→ 取最高类目 → 固定返回该类目 cards 列表前 3 张
    • 局限：只到类目级（非题级/概念级）；路由表只覆盖约 50/243 张卡，八成题卡不可达；无语义匹配；无证据文件；os.walk 无跳过目录/大小限制（大仓库会慢）；无复盘/薄弱优先

    对比结论

    • 它强在知识组织：卡内嵌答案、学习路径边、复习状态
    • 本系统强在项目闭环：概念级路由（match.json + 证据文件）、项目内作答（文件:行号 锚点）、三维评分、复盘、薄弱优先
    • 交互互补：它审代码（架构对齐/坑点预警/演进建议 三维），本系统审人（概念理解/原理深度/落地证据 三维）
    • 它的完整性缺陷：题卡里 [[01_Agent架构与设计范式]] 等分类 wikilink 全部断裂（references/ 只有 03_Cards，无分类笔记）

    融合计划（用户认可方向，未执行）

    1. 答题思路移植：按 Q↔L 映射把 243 卡"答题思路与知识点分析"批量搬进 items.json（用户自家文件，无版权问题）——一举补上"题库无答案"缺口
    2. 学习路径边：prerequisites/downstream 引入概念图谱 → 图谱出现"前置→后置"有向边，学习顺序可视化
    3. 诊断模式：把"架构对齐/坑点预警/演进建议"三维审查姿势作为本技能第二模式（拷问模式审人，诊断模式审代码）
    4. 待复习状态：答错的题自动进待复习清单，下场开场先打（并入复盘机制）

    用户核心设计意图（贯穿始终）

    模块化/分类/图谱的唯一目的 = 路由检索：切分→检索单元；概念词典→路由索引；图谱→检索结果可视化；match.json→定向路由；四层漏斗→按匹配度加载。不是把库塞进上下文，而是把"路由结果"塞进上下文。任何新功能先问"它如何服务路由"。
