    JeecgBoot 面试技术档案（学习谈资，非自研）

    定位：40K+ star 的企业级 AI 低代码平台（"低代码+零代码"双模），类似 Dify 的 AIGC 应用平台 + 在线表单/报表引擎。对 AI Agent 岗的谈资价值：一套基于 langchain4j 的 RAG/Agent/MCP 落地范本，以及低代码平台的元数据驱动设计。以下论断均以本检出源码（v3.9.3）与 README 为准。

    ① 架构与技术栈概览

    • 版本：3.9.3，Spring Boot 4.1.0 + Java 17（支持 21/24/25），MyBatis-Plus 3.5.16，FastJSON2，Druid，Knife4j，Quartz 定时任务（jeecg-boot/pom.xml）。
    • 前后端分离：后端 jeecg-boot/（Java），前端 jeecgboot-vue3/（Vue3 + Vite6 + TS + Ant Design Vue4，480 个 .ts / 469 个 .vue）。
    • 单体/微服务双版本：jeecg-system-api 下 local-api（直调）与 cloud-api（Feign）双实现，靠启动模块换依赖切换；微服务基于 Spring Cloud Alibaba 2025.1.0.0（Nacos/Gateway/Sentinel/XXL-Job），jeecg-server-cloud/ 含 Seata 分布式事务、RabbitMQ/RocketMQ 演示模块；-P SpringCloud profile 激活。
    • 核心模块：jeecg-boot-base-core（框架底座：Shiro/JWT、QueryGenerator、AOP、通用工具）→ jeecg-module-system（用户/角色/菜单/权限/字典，biz+api+start 三层）→ jeecg-boot-module（demo、jeecg-boot-module-airag AI 模块）→ jeecg-server-cloud（微服务）。CLAUDE.md 所述 online/bpm/desform/bigscreen 等 jeecg-boot-platform 模块未包含在本检出，在线引擎仅见演示类 OnlCgformDemoController。

    ② 值得深挖的面试谈资点

    1. 在线表单/Online Coding（零代码引擎）：元数据驱动——配置存 onl_cgform_* 表、运行时动态 CRUD 免生成代码，另有代码生成器 + 手工 Merge 模式（"AI 生成→在线配置→代码生成→手工合并"）。本检出仅演示类 jeecg-module-demo/.../online/OnlCgformDemoController.java；完整引擎在未检出的 platform 仓库，可讲设计思想而非源码。
    2. 权限体系（RBAC + 数据权限）：Shiro 3.0 + JWT 无状态认证（base-core/.../system/util/JwtUtil.java、config/shiro/ShiroConfig.java），按钮/菜单权限 + 注解式数据权限 AOP base-core/.../aspect/PermissionDataAspect.java（@PermissionData + QueryGenerator 拼装 SQL 条件 + JeecgDataAutorUtils）。Sa-Token 为独立分支（README 版本表）。
    3. 缓存策略（Redis 多用途）：字典缓存 base-core/.../aspect/DictAspect.java、动态数据源缓存池 util/dynamic/db/DataSourceCachePool.java、第三方登录 state 缓存 modules/system/cache/AuthStateRedisCache.java、Shiro 会话 Redis 化；WebSocket 广播也借 Redis Topic。
    4. 消息异步与实时推送：单体用 WebSocket（modules/message/websocket/WebSocket.java，@ServerEndpoint("/websocket/{userId}")，sessionPool ConcurrentHashMap + Redis 频道 socketHandler 做跨实例广播）；微服务演示模块提供 RabbitMQ/RocketMQ 监听器；另支持 SSE（McpDemoController 用 SseEmitter）。
    5. AI 应用平台（RAG 管道）：类 Dify 平台，jeecg-boot-module-airag 基于 langchain4j 1.17.2（pom 引入 open-ai/ollama/mcp，见 UPGRADE-langchain4j-1.17.2.md）。RAG 实现 airag/llm/handler/EmbeddingHandler.java：DocumentSplitter 切分 → EmbeddingStoreIngestor 入库 → PgVectorEmbeddingStore 向量检索 → EmbeddingStoreContentRetriever + QueryRouter。
    6. Agent 工具调用与 MCP：AIChatHandler.java 用 langchain4j ToolSpecification/McpToolProvider/TokenStream（流式）；JeecgBizToolsProvider.java 把业务方法（建用户/查用户）注册为 LLM 工具（function calling）；demo/mcp/McpDemoController.java 是标准 MCP Server（SSE 传输）示例；AiragMcp 实体管理外部 MCP 服务器配置。
    7. 查询构造器 QueryGenerator：base-core/.../system/query/QueryGenerator.java 从 HTTP 参数自动构建 MyBatis-Plus QueryWrapper（模糊/范围/数据权限），低代码 CRUD 的基石，可引申讲"参数驱动查询与 SQL 注入防护"。
    8. 事务一致性：单体本地事务（Spring @Transactional）；微服务层有 Seata 演示（jeecg-cloud-test-seata），README 称 starter 提供分布式锁/分布式事务/ShardingSphere 分库分表。

    ③ 与面试题库概念的映射

    • RAG 与知识库 ✅ 真实：airag 模块全链路（EmbeddingHandler、IAiragBaseApi、前端 aiknowledge）。
    • MCP ✅ 真实：langchain4j-mcp + AiragMcp + McpDemoController + 前端 aimcp。
    • Prompt Engineering ✅ 真实：前端 views/super/airag/aiprompts/（提示词管理与实验）+ JPrompt 组件。
    • Redis 与缓存 ✅ 真实：见谈资点 3。
    • ReAct / Agent 工作流 / 意图识别 / 技能体系 / Guardrails / 评测 / AI Coding Agent ⚠️ 命中为 <内容命中> 无文件证据：仓库内无对应实现，可谈"langchain4j 的 AiServices/Tool 机制"但别声称仓库实现了这些概念。
    • LangGraph 与图编排 ❌ 误报：命中文件实为 JustAuth OAuth 登录 state 缓存、前端 qiankun 微前端 state、nodemon.json——与 LangGraph 无关；AI 流程编排是自研（未检出）而非 LangGraph。
    • Agent 记忆机制 ❌ 误报：ActuatorMemoryController 是 JVM 内存监控，memory.ts 是前端缓存工具。
    • 上下文管理与压缩 ❌ 误报：SpringContextUtils 是 Bean 容器工具，其余为前端 ContextMenu。
    • 模型微调与对齐 ❌ 误报：SysUserDepPost 是用户-部门-岗位关系实体，ShiroThreadPoolExecutor 是线程池。
    • 路由机制 ⚠️ 部分误报：命中的是前端 vue-router 动态路由（dynamicRouter.ts），与 Agent 路由无关。

    ④ 最可能的面试追问点

    1. "单体和微服务怎么切换的？"——答 local-api/cloud-api 双实现 + Maven profile，业务代码无感。
    2. "数据权限是怎么实现的？"——答 AOP 注解 + 规则表 + QueryGenerator 动态拼 SQL，能讲清规则注入点。
    3. "AI 对话为什么能调你的系统接口？"——答 langchain4j ToolSpecification + JeecgBizToolsProvider 注册 + MCP 外部工具，流式 SSE 返回。
    4. "向量检索怎么做的？"——答 pgvector 存储 + EmbeddingStoreIngestor/Retriever + QueryRouter 路由，可对比 ES/faiss 选型。
    5. "WebSocket 多实例部署消息怎么广播？"——答 Redis Pub/Sub topic 转发，单机 ConcurrentHashMap 会话池。
    6. （陷阱）"这项目用了 LangGraph 吧？"——答 Java 项目无 LangGraph，AI 编排基于 langchain4j 与自研 flow，能识别误报反而加分。
