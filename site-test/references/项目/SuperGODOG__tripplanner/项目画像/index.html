    一、技术栈与架构概览

    一句话定位：基于 LangGraph + ReAct 的多智能体旅行规划系统——输入出发地+目的地+天数+偏好，输出含预算/酒店/每日行程的 JSON 计划。

    • 编排：LangGraph StateGraph，4 Node（attraction→hotel→memory→planner）+ conditional edge（retry_planner / retry_hotel / done）+ SqliteSaver checkpoint 断点续传
    • Agent：HelloAgents SimpleAgent（ReAct 循环，[TOOL_CALL:...] 语法），4 个 Agent 共享 1 个 AmapToolWrapper 单例；planner 无工具、纯推理
    • 工具：MCP 协议接 amap-mcp-server（16 个工具），Wrapper 三层封装 + FallbackTool 纯本地兜底
    • 记忆：自研 MemoryManager，五因子权重 + 双轨异常检测，JSON 持久化
    • Web：FastAPI + SSE 流式进度；前端 Vue3；LLM 为 DeepSeek
    • 并发：API 层 ThreadPoolExecutor 并行预处理 + 图内 fan-out（START 同时进 memory ∥ attraction，planner 双入边 join）

    二、30 秒自我介绍底稿

    我做了个多智能体旅行规划系统：LangGraph 编排 4 个节点——景点、酒店、记忆、规划。前三个是带工具的 ReAct Agent，通过 MCP 调高德地图；规划 Agent 无工具，纯推理出最终行程。我主要做了三件事：第一，把质量校验做成确定性代码【硬伤/软伤/离群检测】，LLM 只负责生成、规则负责纠错，发现离群景点就触发【retry_hotel 回环】重算质心让酒店重搜；第二，自研【五因子权重】记忆系统，配【双轨异常检测】，用户偶尔住一次豪华酒店不会污染他的经济型画像；第三，全套容错——Error-as-Observation、指数退避重试、MCP 超时保护、SQLite checkpoint 断点续传。

    钩子→代码→追问映射：

    钩子 类型 代码依据 可引向的追问
    五因子权重 / 双轨异常检测 术语 memory/manager.py：final_weight = domain × decay × interaction × frequency_boost × outlier_penalty；价格走 IQR、偏好走频率比（<众数×0.3 判异常，penalty=0.3） 公式怎么定的？为什么两条轨道？
    retry_hotel 回环 架构 graph/nodes.py 离群检测写 center_lng_override；graph/builder.py conditional edge 路由回 hotel Agent 间闭环反馈怎么实现？
    确定性校验 vs LLM 自检 对比 nodes.py _validate_and_refine()：硬伤（缺字段/景点<2/预算超30%）软伤（酒店>10km/暴雨+户外）规则化，MAX_RETRY=3 为什么不让 LLM 自己检查？
    本地计算优先 对比 nodes.py：maps_geo→maps_around→Python 算质心；日期/中心/校验全本地，不交 LLM 哪些活给代码、哪些给 LLM？
    Error-as-Observation 术语 Agent 工具失败返回错误文本而非抛异常，ReAct 循环内决策重试/换参/降级 容错设计取舍？

    三、框架给的 vs 我设计的

    层 框架提供 我设计的
    图编排 LangGraph：Node/Edge/State/conditional edge/Annotated[list, add] reducer/SqliteSaver 4 Node 分工 + START fan-out（memory ∥ attraction）+ planner 双入边 join；三态路由（retry_planner/retry_hotel/done）；error_log 跨 Node 累积约定；离群→override 中心→回环拓扑
    Agent HelloAgents SimpleAgent ReAct 循环 + add_tool() 4 角色划分（景点/天气/酒店/规划）；共享 wrapper 单例只建一次 MCP 连接；planner 故意不挂工具；_run_agent_with_retry 指数退避包装
    工具 MCP 协议 + 16 个高德工具 AmapToolWrapper：Agent 只见 1 个工具，内部 MCP→Format→Validate 三层；POI 并发 maps_geo 坐标增强；10s 超时保护；FallbackTool 纯本地兜底
    生成 LLM 文本生成 硬伤/软伤/离群确定性校验、Haversine 质心计算、画像约束注入（_build_profile_constraints）、JSON 容错解析
    记忆 无 五因子权重公式、双轨异常检测（IQR+频率比）、trip_count≥5 才展示画像、Top-N 裁剪+连续去重、decay=0.95^天数

    四、最可能的面试追问点

    1. LangGraph 与图编排：conditional edge 如何实现 Agent 间闭环反馈？SqliteSaver 断点续传原理？planner 双入边为何能 join？
    2. Multi-Agent 多智能体协作：为什么拆 4 个 Agent 而不是 1 个？共享 MCPTool 单例在并发下是否安全（每次调用新建 event loop、无共享 mutable state）？
    3. Agent 记忆机制：五因子每项的动机与取值依据？0.95 衰减、0.3 惩罚、5 次门槛怎么来的？Top-N 与去重策略？
    4. 容错限流与高可用：Error-as-Observation 与 try/except 的取舍；重试上限耗尽后的降级链路（硬伤降软伤强制 done → FallbackTool）；MCP 超时实现（ThreadPool + 10s）。
    5. ReAct 与工具调用：[TOOL_CALL] 自定义语法与原生 function calling 的对比；工具失败后 Agent 如何重试/换参/降级。
