# Q449: TensorFlow 算子适配与团队职责交付：在 AI 基础设施团队中，如何定义清晰的上下游交付边界？针对特定计算场景适配定制 TensorFlow 算子时，输入输出规范、生命周期、性能指标与正确性验收流水线应如何设计？

> [!QUESTION] 问题描述
> 团队职责与算子工程交付：在 AI 基础设施团队中，算子开发/适配工作的上下游协作边界是什么（与上游算法模型团队、下游推理/训练部署框架团队）？针对特定计算场景适配定制 TensorFlow 算子时，输入输出规范、内存分配、性能指标与正确性验收流水线应如何设计？

> [!SUCCESS] 审查重点与证据要求
> - **必答点与核心考点**:
>   1. **上下游交付契约**: 上游对接算法团队明确输入输出 Tensor 维度、排布（Layout 如 NCHW vs NHWC）与数据类型约束；下游对接部署框架交付 C++/CUDA 动态共享库、Shape Inference 推导函数、Python API 与 CI 验收用例。
>   2. **设备内存托管**: 显存分配必须使用框架原生的 `OpKernelContext::allocate_output` / Allocator 接口，交由 TensorFlow BFC 内存池统一生命周期管理，严禁在 Kernel 内部脱离生命周期随意直接调用裸 `cudaMalloc`。
>   3. **正确性与性能验收流水线**: 构建自动化精度比对流水线，利用 Python 参考实现或纯 CPU 实现进行前向输出一致性比对与反向数值梯度校验（Gradient Check）；并在不同 Batch Size、Sequence Length 维度下建立基准延迟与吞吐档案。
> - **追问方向**:
>   1. 动态 Shape 与静态 Shape 编译分支在 OpKernel 中如何处理？在某些极端变长输入下如何避免显存碎片与频繁重分配？
>   2. 如果算法侧反馈在特定输入组合下算子出现数值 NaN 或 OOM，你的分级排查路径与降级防线是什么？
> - **易错边界与认知陷阱**:
>   - 严禁将“算子交付”片面理解为仅交付单点 Kernel 代码；工程化交付必须包含 Shape 推导逻辑、边界防御性校验及端到端自动化测试用例。
>   - 候选人若未经历过真实大生产交付，容易遗漏算子内存泄露检测与跨框架版本兼容性测试。
> - **验证证据与技术事实一手来源**:
>   - TensorFlow Custom Operators Guide: https://www.tensorflow.org/guide/create_op
>   - TensorFlow GPU OpKernel Design: https://github.com/tensorflow/tensorflow/blob/master/tensorflow/core/framework/op_kernel.h
